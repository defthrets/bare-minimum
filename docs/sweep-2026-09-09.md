# Bug sweep, 9 September 2026

Four audits plus a scripted whole-repo pass. Every finding below was verified by reading the
code directly; anything an audit claimed that did not hold up was dropped. Nothing here has
been changed.

Severity is about what the player actually loses, not how hard the fix is.

---

## A. Leaves the game broken after the mod is off or unloaded

These are the worst class: the mod changes game state and never puts it back, so the damage
outlives the feature and, in three cases, the script itself.

**A1. Turning the vitals off while winded caps your movement and disables your special
ability, permanently.**
`VitalsHud.Update` returns at `if (!on)` *before* `_energy.Update`, and `Energy.Release` is the
only thing that lifts `SET_PED_MAX_MOVE_BLEND_RATIO` and re-enables the special ability.
Sprint until the bar empties, then switch the mod off in F7: you jog for the rest of the
session with no special ability, with the mod off. The class comment claims `Release` covers
exactly this.

**A2. The notification lift keeps displacing the game's feed with the mod switched off.**
`Placement.Notifications` runs at the top of `Placement.Update`, which is called before the
same `!on` gate. Every notification stays pushed up 4.5% of the screen until the script
unloads. Introduced today.

**A3. Interiors are pinned in memory and never unpinned.**
`PIN_INTERIOR_IN_MEMORY` and `SET_INTERIOR_ACTIVE` are called on every walk-in. There is no
unpin anywhere in the codebase. The pins are refcounted and outlive a script reload, so a
session of shopping raises the floor on interior memory with nothing able to release it.

**A4. The world can stop streaming for the rest of the session.**
Entering a room starts a 40 m load scene and stops it forty lines later, inside the same
`try`. The `catch` unfreezes, repositions, switches the map back and fades in, but never stops
the load scene. There is an up-to-eight-second wait between the two.

**A5. The game's own health and armour strip can stay missing.**
`Stock.Show` calls `Setup` once and discards the `bool` it returns. `Setup` does nothing and
returns false when the minimap scaleform is not ready, and there is a two second back-off. The
`_hidden` flag has already flipped, so nothing retries. Turn the vitals off in that window and
the vanilla strip is gone for the session, with nothing in the log.

**A6. The movement cap is orphaned on the previous character across a switch.**
`_cappedPed` holds one handle and is overwritten unconditionally. Go winded as Franklin, switch
to Trevor before it refills, and Franklin keeps the cap with nothing left that knows about him.

**A7. The online map is never switched back if you die inside a room.**
`Leave` calls `Mp(false)`; `Forget` does not, and `Forget` nulls the room, which is the only
thing `Shutdown` has to go on. Latent today because every shipped room is offline, but it is a
documented, supported field.

**A8. Requested map chunks are never removed.** `REQUEST_IPL` appears twice, `REMOVE_IPL` never,
including on the path that gives up on the room after requesting it. Latent for the same reason.

## B. Data loss

**B1. A save that exists but cannot be read is treated as a new game, and then overwritten.**
`JsonFile` has a three-state result specifically to separate "no file" from "there is a file
and I could not read it", and its own comment says treating the second as the first "is how a
playthrough gets overwritten by a blank one on the next autosave". All four callers collapse
both into one branch, and the pantry does not even ask. A backup tool holding `needs.json` open
for the moment the script loads is enough: the mod starts everyone at full and, ten seconds
later, writes a file containing only the current character. The other two protagonists' needs
are gone, and the same applies to `pantry.json` and `fridge.json`. `JsonFile.BackupOf` exists
and has no callers, so there is no recovery path either.

**B2. An item is destroyed if the pocket cap was lowered.**
The take-then-put-back pattern in the reflection bridge and the pocket assumes the put-back
cannot fail. It can: the cap is read live and can be set below what you are already carrying,
so `Add` refuses and the item is simply gone. The class comment claims this pattern has neither
a duplication nor a theft bug.

## C. Input firing on presses that never happened

**C1. A shop shelf opens by itself.**
The hold-to-open state is only updated inside the door block, below four early returns. Hold E
at a shop door, back off before the hold matures, let go, walk back: the first frame in reach
sees a release that never happened. Every shipped door has a menu, so today it is a stray
shelf; a door configured without one would buy and eat an item with no key pressed.

**C2. The fridge opens itself if you walk up holding E.**
Same shape. `_keyWasDown` is only written inside `Offer`, which returns early three times, so
it is stale whenever you are not already standing at a fridge. E is also the vanilla context
button, so holding it while walking is ordinary.

**C3. The settings menu opens off a press it deliberately ignored, and its own chord fights
its navigation.**
The pad chord is left bumper plus up, which are the menu's own tab-back and move-up. Opening it
moves the cursor on the first frame; paging tabs while it is open closes it. Separately, a press
made while the panel is suspended fires when the suspension lifts. The pocket hit this exact
class of bug and fixed it deliberately; this screen has no equivalent.

## D. Performance

**D1. Three scanners run a full model sweep every frame.**
The throttle reads "if we are inside the window *and* we already found something". When nothing
is near, which is nearly always, it falls through and rescans. Fifteen to twenty closest-object
searches per frame, continuously. The same line is in the counter, bed and fridge scanners, and
each is called every tick.

**D2. The minimap anchor is queried three to four times a frame.**
Each query is four natives and mutates the script's global draw alignment, for a value that
changes only with the resolution or the safe-zone slider. The same query is cached on a 500 ms
clock elsewhere in the same class, with a comment saying there is no reason to spend it. Each of
those calls also rebuilds the row and re-parses the row order string, roughly two thousand
throwaway strings a second.

**D3. Rounded panels cost more the bigger your monitor, and ignore the draw budget.**
The corner band height floors at one pixel, so the rectangle count scales with screen height
rather than with the step count it is given. A panel is about 79 rectangles at 1080p and about
107 at 1440p. Nothing in the panel path checks the budget, so opening the pocket on a 1440p
screen can spend most of the frame's allowance before the HUD draws, and the bars quietly lose
their specks.

**D4. The cart discovery sweep never stops and gets slower as it succeeds.**
Every three seconds, forever, with a linear walk of a list that only grows and a model
allocation per prop per row.

## E. Settings that do not do what they say

**E1. Your `[HUD] Size = 0.004` is rejected 362 times.** The clamp floor is 0.005. The code's own
comment says people reach for Size to drag the bars down and that they should not, because on
the bar style it only moves the foot. The honest fix is to stop Size touching the foot at all,
which would shift your row by about 0.011 and needs HudY compensating at the same time.

**E2. Your `[HUD] BarIconScale = 1.55` is clamped to 1.** Your marks are smaller than you set.

**E3. `[Speech] Locations` and `LocationChance` were written into `[Social]`.** The code reads
them from `[Speech]`, so they cannot be set. Introduced today.

**E4. `[Drink] DrunkAt = 0` pins the drunk walk on permanently, stone sober**, and turning the
drink system off does not stop it, because the sober value is also zero and `0 >= 0`.

**E5. `MinMoveRate` below 0.4 does nothing.** A downstream floor overrides it, and the range
accepts 0.3.

**E6. `WellFedAbove = 1.0` disables the bonus** instead of granting it only at a full meter,
because an earlier test always wins.

**E7. `[Social] GapSeconds` has no range.** A large value overflows to a negative and removes the
gap entirely, which is the opposite of what the setting means.

## F. Noise and polish

**F1. The fridge screen has the same card overflow the pocket had.** The fix went into the
pocket only; the fridge still has the hardcoded height and its flavour line lands on the footer
rule.

**F2. The cash readout is drawn two columns left, over the bars.** It is positioned from a row
built before the upright flag is set, so the row has two slots instead of four. The same stale
row is published to Fumes, which can place the fuel gauge two slots left whenever the gauge
draw returns early.

**F3. The log is nine tenths repeated warnings.** Three permanent conditions account for 637 of
about 700, which buries everything else.

**F4. The log only rolls over on the first write of a session**, so a long session at debug level
grows without bound. My note about the cart harvest being at risk from a mid-session roll was
wrong for this reason.

**F5. Discovered carts warn 42 times about a stand prop they do not need**, telling you to fix a
vendors.json entry that does not exist.

**F6. Apple and beans_bread have no prop that exists in this build**, so they are eaten
empty-handed and warn 233 times about it.

**F7. `Vendors.Spawn` is dead code.** Nothing calls it.

**F8. Documentation drift.** The ini says the starvation health floor is a sixth of maximum; it
is a third, and the code comment records the change. Three sleep and hunger figures in the
settings comments no longer match their fields.
